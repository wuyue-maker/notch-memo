## 1. 实现方向

已采用 Swift + AppKit + SwiftUI 构建独立 macOS 应用：AppKit 管理悬浮面板、屏幕位置、窗口层级和焦点，SwiftUI 负责任务清单与基础动画。窗口已在目标系统运行，访达全屏显示与编辑通过一轮验证；其他场景继续验收。

### 需要先验证的系统能力

| 能力 | 拟验证方式 | 判断标准 |
| --- | --- | --- |
| 刘海附近定位 | 使用 NSScreen 的屏幕与安全区域信息计算热区 | 不依赖具体 14/16 英寸型号的硬编码，位置正确 |
| 跨桌面显示 | 验证 NSWindow 的 Spaces 行为 | 当前桌面能展开，不主动切换桌面 |
| 全屏显示 | 评估 NSPanel 与全屏辅助窗口行为，必要时评估当前 SDK 提供的其他集合行为 | 在实际全屏软件上可唤出和编辑 |
| 悬停不抢焦点 | 分离显示、单击展开全文与显式编辑 | 悬停或展开任务不会把其他应用的输入转移给便签 |
| 隐藏热区 | 验证鼠标位置检测与面板命中区域 | 无可见残留，不拦截大范围点击 |

Apple 文档提供了[屏幕安全区域信息](https://developer.apple.com/documentation/appkit/nsscreen/safeareainsets)、[所有 Spaces 显示行为](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct/canjoinallspaces)和[全屏辅助窗口行为](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct/fullscreenauxiliary)。这些 API 为方案提供依据，但文档并不能证明本应用已兼容用户的 macOS 27 环境。

窗口集合行为的部分选项互斥，具体组合需对照[当前 SDK 的定义](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct)验证。普通窗口置顶、所有 Spaces 和全屏显示分别验证，不能视为同一能力。

### 工具与环境核对

已读取实际环境：macOS 27.0.1（26A434）、Xcode 27.0、Swift 6.4、arm64。通过 Swift Package 构建，使用本机临时签名生成应用。

工程部署目标为 macOS 14；目前仅对本机系统进行构建和部分界面验证。开发版本以本机运行验证为目标；公开分发、签名公证与安装包发布单独安排。

## 2. 模块与数据

| 模块 | 责任 |
| --- | --- |
| 应用入口 | 启动、菜单栏备用入口、退出 |
| 屏幕布局 | 获取内置屏几何信息，计算热区、连接区和面板边界 |
| 面板控制 | 置顶、全屏、显示与隐藏、输入焦点 |
| 交互状态 | 悬停计时、自动收起、固定、编辑和拖动保护 |
| 任务存储 | 添加、编辑、完成、恢复、排序、删除撤销和本地持久化 |
| 界面与动画 | 纸质面板、任务行、已完成区、揭纸和弹性勾选 |

### 最小数据模型

| 对象 | 建议字段 |
| --- | --- |
| 任务 | 唯一 ID、文本、创建时间、更新时间、完成时间（可空） |
| 清单 | 数据格式版本、任务集合、未完成任务 ID 顺序 |
| 临时删除记录 | 被删除任务、原分组与位置、撤销截止时间；仅保存在内存 |
| 会话状态 | 是否固定、已完成区是否展开、当前编辑任务、拖动与动画状态 |

完成状态由完成时间是否存在确定，避免两个字段相互矛盾。未完成顺序以 ID 数组为准；已完成列表按完成时间排序。恢复任务时追加到未完成顺序末尾。

### 本地保存

- 首版拟使用用户应用支持目录内的版本化 JSON 文件，由单一存储入口串行写入。
- 在语义变更提交后保存：添加、编辑提交、排序结束、完成、恢复、删除与撤销。
- 采用临时文件替换的原子写入方式，保留最近一次有效备份；具体实现随工程确定。
- 保存失败时保留内存中的任务和待写入状态，显示“保存失败，点击重试”，不能显示为已保存。
- 启动读取失败时保留原文件，尝试有效备份，并提示恢复情况，避免用空清单覆盖损坏数据。
- 第一阶段的临时面板不宣称具备可靠存储能力；进入日常试用前完成保存与恢复验证。

## 4. 状态实现约束

- 展开模式、输入状态、拖动状态分别建模，避免把“固定”“编辑”“等待收起”混成互斥状态。
- 所有悬停计时器可取消；每次实际隐藏后清理过时计时和动画回调。
- 正在输入法组合、编辑或拖动时，自动收起保护优先于离开延迟。
- 固定只阻止自动收起，不阻止用户显式收起，也不阻止锁屏隐藏。
- 勾选引起的数据变更即时记录；延迟移行动画只影响显示，避免退出时丢失完成状态。
- 同一任务的连续点击、删除和撤销都以最终数据为准，过时动画不得重新插入任务。
- 锁屏或会话不可用时隐藏；解锁后恢复检测，不自动展示内容。

## 5. 验证方法

### 自动检查

进入代码阶段后，只为关键逻辑建立有意义的测试：任务排序和恢复、批次撤销、本地读写及损坏恢复、收起保护与计时取消。构建检查按实际工程工具链执行。

### 实机场景

| 场景 | 操作 | 观察结果 |
| --- | --- | --- |
| 普通桌面 | 热区短暂经过、停留、离开、快速返回 | 无明显误触，展开收起符合计时 |
| 输入焦点 | 在其他应用输入时悬停，再点击便签输入 | 悬停不中断原输入，点击后可编辑 |
| 中文输入 | 使用拼音候选、回车选词、Escape、点击外部 | 无误添加、丢字或意外收起 |
| 固定 | 固定后移出，取消固定，点击收起 | 状态与产品规则一致 |
| 全屏软件 | 浏览器原生全屏、视频全屏、其他常用全屏应用 | 可唤出，不主动退出全屏或切换桌面 |
| Spaces | 切换桌面后唤出，固定时切换桌面 | 面板位置正确，行为一致，无残留窗口 |
| 拖动排序 | 跨多行拖动、边缘滚动、无效区域释放 | 顺序正确，可取消，重启后保留 |
| 连续操作 | 连续勾选、取消完成、删除后撤销 | 无重复任务、错位或过时动画覆盖 |
| 数据恢复 | 修改后退出重启，模拟写入和读取失败 | 有效数据可恢复，失败不覆盖原文件 |
| 屏幕与会话 | 缩放变化、睡眠唤醒、锁屏解锁 | 热区重新定位，任务不意外露出 |
| 长列表 | 空清单、长中文、30 条以上任务 | 布局与滚动正常，操作入口可达 |
| 减少动态效果 | 开启系统对应设置后操作 | 动画简化，操作仍完整可用 |

实机验证必须记录系统版本、测试应用和结果。未执行的场景保持“未验证”，不能以自动测试通过代替。
